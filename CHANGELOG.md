# Changelog

## Unreleased

Agents can now start Converoom when it isn't running, for products you choose. Connect a product with `converoom connect PRODUCT --auto-start`, and a tool call from its agent that finds no runtime starts the installed runtime in a new window, waits up to 15 seconds for it and sends the call once. The pairing code appears only in that window, never in the agent's conversation, shared access stays off, and agents starting at the same time share one runtime. Auto-start is off by default, `converoom doctor` shows it for each product, `converoom upgrade` keeps it, and a plain `connect` or `disconnect` turns it off. Without it, a tool call while Converoom is stopped now returns `runtime_unavailable` with the command to start it, marked as not done and safe to retry, instead of a bridge error, and the room skill tells the agent to ask you rather than run the command itself.

The package now declares that it runs only on Windows x64, so npm refuses to install it on other platforms instead of the CLI stopping on its first run.

Cancelling a turn that is still waiting for your approval now withdraws its approval request as well, and the room history records it. Previously the request stayed in the Approvals queue for up to an hour after the turn was cancelled.

When an approval request is withdrawn because its turn was cancelled, a round robin was stopped, the room closed or a room budget was used up, the room history now records who withdrew it, what it would have allowed and the room policy in force, as it already did when a member was removed. Previously it recorded only that the request was cancelled, by the runtime.

Agents in a room can now wake each other. When an agent asks, reviews or challenges a managed agent with a structured mention, the runtime queues a turn for that agent instead of waiting for the host. Each agent takes one such turn at a time, later questions wait, and you still grant every turn before it runs. If the agent's owner has not allowed it or the room's limits would be exceeded, nothing is queued and the room history says why. Mentions an agent posts while answering count toward the room's mention hop limit, so chains of questions end. This is on for new rooms. Rooms created before this version keep host-led turns until you choose Allow agent wakes in Room controls, and Stop agent wakes turns it off again. You can also run a round robin: choose the speakers in order, the number of rounds and one prompt, and approve the plan once. Your approval covers each managed turn in the plan. The room runs the turns one at a time and keeps going if the host disconnects. It stops at the first turn that does not complete, when you stop it, or when the room closes. A host agent can propose a plan with `round_robin_propose`, which waits for your approval, and stop it with `round_robin_stop`. Room budgets apply to both, and plans are included in room exports.

Rooms now have a lifecycle and, separately, a phase. The lifecycle replaces open, paused and closed with draft, active, pausing, paused, completed, cancelled and archived. Create a room as a draft to add agents and limits before anything runs; its time budget starts when you start it. Pausing a room with work in progress shows Pausing until that work stops, then Paused. Closing asks whether the room completed or was cancelled, with an optional reason. A cancelled room records a handoff of what is still open, as a used-up budget does. Closing also withdraws the approvals that queued turns were waiting for and records each cancelled turn. A completed room can be archived, which moves it to the end of the room list. The phase follows the work through deliberation, decision proposed, owner review, execution, verification and handoff. Proposing a decision moves the room to decision proposed, and the host can ask for your review. Only you approve it for execution or a handoff, or send it back to deliberation, and approving grants no execution: every managed turn still needs its own grant. The room view shows the phase above its gauges, and the room history and Markdown exports record every change with its reason. Agents get `room_start`, `room_set_phase` and an outcome and reason for `room_close`. The room store moves to schema version 2 when the runtime next opens it, or during `converoom upgrade` after the backup. Open rooms become active, paused rooms stay paused, closed rooms become completed, and rooms with a proposed decision start in decision proposed. Earlier versions cannot open the migrated store, and `converoom recover --rollback` restores the pre-upgrade backup. Restored history now opens as archived, or cancelled for a cancelled room.

Saved agent bridge credentials and shared-room connection tokens are now kept in Windows Credential Manager. Their files in the data folder keep only a reference, so copies, backups and synced files of the data folder no longer contain them. Existing credentials move the next time the runtime starts, or during `converoom upgrade`; `converoom disconnect`, `remote-disconnect` and `converoom uninstall` delete them again. Programs running as you can still read Credential Manager, so this does not separate Converoom from them, and `converoom doctor` and `converoom start` now say which store is in use, what it protects and what it does not. If Credential Manager is unavailable in the session, credentials stay in the private files as before and the reason is shown. Set `CONVEROOM_CREDENTIAL_STORE=file` to keep using private files. The runtime's control token, created at each start, and the per-turn credentials of managed sessions stay in private files.

Coding workspaces can now be cleaned up from a preview. `converoom cleanup`, or Workspace cleanup in the Work view, lists every attempt, combined candidate and check clone with its room, task, size and either that it can be removed or why it is kept. A clone can be removed once its work is submitted or recorded and the room has been exported since. A released attempt also needs 7 days to pass and no unsubmitted changes. Dirty, unexported and uncertain work is always kept, and nothing is removed automatically. `converoom cleanup --confirm CODE` removes only what that preview listed, with the clone's temporary build and test folders, and removes nothing if anything changed since the preview. Removals are recorded in the room's history, and one that stops partway finishes on the next cleanup. Previously cleanup removed one submitted attempt at a time by ID, accepted any earlier export of the room, and never removed check or candidate clones. `converoom cleanup --attempt ID --confirm` still works under the same rules.

A room whose message, turn or time budget is used up now stops taking new work and records a handoff. The handoff appears once in the room's history and in Markdown exports. It lists the latest agenda and proposed decision, open questions, the queued turns that were cancelled, answers kept for the owner, uncertain turns and open coding attempts. It never accepts a decision or approves anything. New turn requests are refused with the `budget_exhausted` error code, and the response says nothing was committed. When messages or time run out, queued turns and the approvals they were waiting for are withdrawn, because none of them could post an answer. Turns accepted within the turn budget still run, and a turn that is already running finishes. Previously, queued turns were cancelled one at a time without a record, and a turn waiting for approval stayed queued. Raising a limit you lowered lets the room continue. The room view shows the handoff, marks the room as Budget used up and turns off requests that would be refused. Rooms that ran out of time before this version record their handoff when the runtime next starts. Budget refusals that used the `budget` error code now use `budget_exhausted`.

New `converoom upgrade`, `converoom recover` and `converoom uninstall` commands manage the installation. Converoom now records which installed version is active, and running a different package no longer changes it as a side effect: `start`, `setup`, `connect` and `onboard` refuse and name the installed version. Upgrade backs up the room store and artefacts, installs the new runtime, moves every connected product to it without issuing new credentials and refreshes room skills you have not edited. The previous version is kept, and downgrades are refused. Recover finishes an interrupted upgrade, clears what a crashed runtime left behind, repairs the runtime's files and fixes stale registrations; with `--rollback` it returns to the previous version. Uninstall shows what it would remove first, then revokes Converoom's credentials and removes only what Converoom owns. Room data stays unless `--delete-data` repeats the data folder's path. Rerunning a newer Windows bundle now upgrades instead of running setup again.

Every room now shows its whole history. The browser used to receive the 1,000 most recent events from all rooms together, so a room whose events had been pushed out of that window opened with an empty timeline and no messages. It now loads the open room's records and its newest 1,000 events, and Load earlier events pages back through the rest. The state the browser reloads after each room event also no longer carries every turn, approval and interaction ever recorded: apart from the open room's, it holds only the approvals waiting and the turns in flight in other rooms. With a 10,000-event history across 48 rooms on the same machine, a reload is 34 KB instead of 2.5 MB and takes up to 34 ms at the 95th percentile instead of up to 227 ms. Your own post now appears within 55 ms instead of 251 ms and an agent's within 45 ms instead of 320 ms, and the idle daemon's working set stays at 104 MiB instead of reaching 224 MiB.

The local browser now receives each room event as soon as it is stored. Its event stream used to check for new events every 750 ms, which was most of the time an agent's post took to appear. Under the reference load on the same machine, an agent's post now appears within 43 ms at the 95th percentile, down from 754 ms.

Every authority change now leaves a complete audit record: who made it, a digest of exactly what changed, its scope and expiry, and the room's policy version. This now also covers seat consent, policy changes (with the new values and previous version), host transfers (with the request and previous host), permission grants and denials, pending membership expiry, and room-connection approvals and revocations. It also covers the participant's connection, proposal accept and decline, and disconnect decisions. Changes that belong to no room are recorded as append-only audit records: local bridge credentials when issued or revoked, pairing codes when issued, and each browser or CLI session a pairing code opens. No record contains the credential or code itself.

Markdown exports are now readable transcripts instead of event data in JSON blocks. `converoom export ROOM --output room.md` lists every numbered event in order with who acted and when. Messages, agenda and decisions show their text, turn requests their prompt, and approvals their exact scope and digest; every other change gets one line. The file names the digest of the JSON export it was rendered from, and only the JSON export can be restored. The shared room's export pages read the same way, limited to the public history, with the page's event range and the room's shared artefacts and their digests. Recorded text sits in fenced blocks, names are escaped, and control and bidirectional characters are replaced, so nothing an agent writes can pass for a transcript heading or an approval.

`converoom doctor` now reports, for each product, whether its Converoom registration is present and points at this data directory, and whether the saved bridge credential is still active. It reads only Converoom's own entry in the product's MCP config, and checks the credential with the running runtime without printing it. `connect` records the config path it used, so a registration made with `--config` is checked in the right file.

Managed Cursor sessions now authenticate only with Cursor's advertised `cursor_login` method, as Grok and Antigravity already did with theirs, and refuse to start without it. Cursor's auth-token variable is now removed from managed processes along with the API keys. `converoom doctor` describes this and Kiro's CLI-owned sign-in.

A turn's full record now shows its execution evidence: when dispatch was committed, which native session ran it and whether the session's stop was confirmed, the outcome code, any cancel request, the posted answer and that containment is advisory. After checking an uncertain turn you can record what you found (the agent acted, did not act, or it is still unclear) with a private note. The turn stays uncertain, nothing is rerun, and its seat stops showing the warning.

`converoom disconnect` now finishes when you have edited the installed room skill. It keeps the edited skill, says where, and still removes the product's Converoom registration and saved credential. Previously it stopped after revoking the credential, leaving a registration that could no longer connect.

Claude Code and OpenCode seats can no longer be added as managed sessions, which they cannot run; they join through their own MCP conversation. Observers are no longer offered turn, reply or coding-worker choices the room would refuse, and seat cards show declared, probed and tested capabilities separately. Pausing or resuming a room from the index now reports a refusal instead of ignoring it, and confirming a host transfer explains that it hands over orchestration and authorises no execution.

A participant whose shared-room connection stalls under a slow network no longer misses an event, which could happen when a keep-alive filled the connection while the next page was read. A browser that reconnects to the local event stream with a position the store does not hold is told to resync instead of losing live updates until the page is reloaded.

`converoom doctor` reports, for each product, what a managed session verifies about the native sign-in before inference.

The monospace font's extended Cyrillic subset now loads. The build embedded it in the stylesheet as a data URL, which the content security policy of both the local and shared listeners refuses, so every page load logged a policy violation and those characters fell back to another font. Every interface asset is now served as a file.

Managed turns that time out, lose their native process or are cancelled without the vendor confirming it are now recorded as uncertain rather than failed, because the agent may already have acted. A turn is recorded as failed only when it never started, for example when the vendor refuses the request over quota or sign-in. It is also failed when the vendor reports its own final outcome or the room refuses its answer. Codex cancellation is now confirmed the same way as the ACP products, including a cancel sent while the turn was still starting. Uncertain turns keep their reason in the UI, and a coding worker's reservation can be released once its process stop is confirmed.

Polling claims now have a lifetime. A claimed turn that is not completed within its turn time budget, or a cancellation the agent does not acknowledge within a minute, becomes uncertain and frees its active-turn slot instead of blocking dispatch until restart. Participant daemons report failed local turns, pass host cancellation to the local session and acknowledge it, and end native work early enough to publish within the host's claim budget. The shared listener now rate-limits each authenticated principal separately, so one participant or anonymous traffic cannot exhaust another's budget, and a rate-limited or unreachable poll no longer cancels accepted local work.

Managed turns no longer start once the room's message budget is used up; they are cancelled with a visible reason, as the time budget already was. If the room refuses an answer after a turn has started, the turn fails with that reason and keeps a redacted copy of the answer, up to 1 MiB, in its turn record for the owner to read. The copy is not added to room history or shared with other members.

A participant's local room for managed remote discussion no longer stops accepting proposals 90 minutes after it was enabled. It stays bounded by the connection's turn budget, per-turn time and the approval of each turn, and rooms created by earlier versions are repaired when the daemon restarts.

Read commands no longer store their results under a client key. Exports and shared artefact reads run again each time, so repeating one with the same key returns current, integrity-checked data, and the database no longer grows with every export. Read results stored by earlier versions are removed at startup.

Shared artefacts accept ordinary technical Markdown, such as "metadata:", generic types like `Map<string, number>`, autolinks, comments and inert formatting tags. Script-capable elements, event and style attributes, and script or data links (including entity-encoded ones) are still refused. The check now runs in linear time; the previous pattern could stall the daemon for minutes on a crafted 1 MiB upload.

Remote turn proposals now carry the shared room's title, objective and latest public conversation, and the local managed prompt no longer substitutes the local proxy room's objective. Participant connections no longer read room history on every poll, halving their steady request load. The browser apps follow an update that arrives during a refresh with one more refresh instead of waiting up to 12 seconds. The local listener rate-limits each agent credential and browser session separately, so one busy agent cannot exhaust the others' allowance.

Stored command results now expire. Repeating a command with the same client key returns the stored result for at least a week; after that it runs again. Expiry runs at startup and hourly in batches of 1,000 results, so a large backlog never stalls the daemon. Results stored by earlier versions expire a week after upgrade. The database format is unchanged, so earlier versions can still open it. Token exchange and renewal on the shared listener are now rate-limited per credential holder, so anonymous traffic cannot block them. A participant whose renewal is rate-limited keeps its credential and retries instead of needing to reconnect.

Workspace commands such as repository registration, task claims and submissions keep their recorded outcomes for the same week. A failed workspace command no longer blocks its client key permanently; after a week the key runs again. A command interrupted mid-run still blocks its key until the work is inspected. Owners can now list interrupted commands with `converoom interrupted`, including when each started and which repository, task or attempt it named. After checking the work, `converoom interrupted-clear ID` lets the key run again. A command still running in the daemon cannot be cleared, and clearing one that belongs to a room is recorded in that room. The Work view lists them under Interrupted commands, with an Inspect and clear action.

Added a Windows installation bundle with a checksum-pinned Node runtime, compiled app, production dependencies, SQLite/supervisor prebuilds and licence notices. One installer installs missing Git and Tailscale plus selected supported native clients, creates durable launchers and starts guided local MCP/skill registration. Account sign-in and shared HTTPS activation remain explicit. CI builds and smoke-tests the extracted bundle before making it available as an artefact.

Added Antigravity, Kiro, Qoder and Grok Build across MCP registration, room schemas, product selection, diagnostics and participant-local connections. Added managed ACP profiles using official native entry points and native authentication, with scoped room tools, one-time approvals and cancellation. Grok API-only authentication is rejected; Antigravity requires Google's separate ACP server. Live acceptance for the new vendors remains pending.

Managed ACP coding supports approved file read/write and literal-argv terminals in the assigned workspace. Client operations check canonical paths, bind writes to content digests, bound file/output size and stop owned terminals on completion or cancellation. Discussion sessions keep these capabilities disabled.

Fixed ACP replies accepting other sessions' public messages. ACP adapters now check the negotiated protocol version, retain Kiro consent metadata, bound public output and reject overlapping prompts. Native processes also clear the new vendors' API-key environment variables. Added agent setup documentation and protocol/configuration regressions.

## 0.2.0 (Windows V1.1 preview, 10/10/2026)

Updated architecture, setup and progress documentation for the implemented P0 through P5 workflow, P6 package evidence and remaining acceptance gates. Documented the separate shared listener, participant-owned execution approval, recovery and actual environment/CLI configuration.

Added confirmed human memberships, independent owner consent, a separate opt-in private HTTPS/MCP listener, PKCE participant connections and participant-local execution approval. Added scoped shared browser state, streams, structured MCP results, resources/prompts, immutable reviewed text artefacts and bounded public Markdown exports. Members, Connections and Artefacts support invitation, denial, revocation, identity recovery and reconnect at desktop and mobile widths.

Managed turns recheck requester membership and exact consent before startup, during execution and before publishing. Participant admission binds the accepted sender and budget. Shared message reads update public receipts. Interrupted OAuth setup becomes visibly uncertain; expired browser sessions recover through a bound owner-issued code. Partial installation repair preserves an active runtime's payload.

Local Windows fixtures and package checks provide preview evidence only. The real two-Windows/Tailscale pilot, actual vendor permission/cancel/quota observations, fresh users, manual accessibility and exact new remote CI remain pending. No registry publication or deployment occurred.

Queued turns and approvals survive pause/resume. Vendor approvals resolve at their callback deadline, and polling agents can explicitly claim and complete their own turns. Restore validates and imports history atomically; redacted exports retain valid digests. Indexed history queries and bounded event streams reduce recurring scans. Windows canonical-path assertions account for short-path aliases. V1.1 private shared-room work follows the approved design; verification and release scope remain Windows x64 only.

Fixed mixed-case workspace digests, supported CRLF apply, public environment templates and approval/submission lifetimes. Added safe retained-reservation release, per-turn scoped managed MCP tools and polling-host coding orchestration. Removed installation-token access to human commands and pairing codes. Updated public requirement links and fixed mobile dialog path wrapping. Live vendor/platform acceptance remains open.
